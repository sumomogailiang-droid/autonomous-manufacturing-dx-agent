# Codexチームのセットアップ

ENGULF 制作部門 Codexチーム（design / telop / mixer）を、Codex CLI で動かすための手順です。

## この作業は人が行います

**サインインは人がローカルで行ってください。** Claude Code 側からアカウントへログインすることはできませんし、
認証情報を Claude Code へ渡す必要もありません。パスワードやトークンをチャットへ貼らないでください。

```bash
codex login          # ブラウザが開くので、使用するアカウントでサインイン
codex whoami         # 意図したアカウントか確認する
```

利用アカウントは各自の運用に従ってください。アカウントのメールアドレスや契約プランを
このリポジトリのファイルへ書かないこと（Gitへ入ると共有範囲を超えます）。

## MCPサーバーへ接続する

`~/.codex/config.toml` へ追記します（`agents/codex-config.toml` の内容そのまま）。

```toml
[mcp_servers.video-manual]
command = "node"
args = ["/絶対パス/autonomous-manufacturing-dx-agent/agents/mcp-server.mjs"]
```

接続できているか確認:

```bash
codex
> list_agents を実行して、役割一覧を見せて
```

10役割が返れば接続できています。返らない場合は `args` を絶対パスにしてください。

## Codexの画像機能を、どの役割がどう使うか

| Codexの機能 | 使う役割 | 用途 | 呼ぶ前に必須 |
|---|---|---|---|
| 画像生成 | `design` | 図解・アイキャッチ・サムネイル案の生成 | `get_design_rules` |
| 画像認識（読み取り） | `design` | 生成物・既存素材が制約を満たすか目視検査の補助 | `get_design_rules` |
| 画像認識（読み取り） | `telop` | 演者の判別、テロップが顔へ被っていないかの確認 | `get_numeric_standards` |
| 画像認識（読み取り） | `mixer` | 演出箇所の特定（画角変化・デザインテロップの検出） | `get_numeric_standards` |

### 生成前に必ず引く制約

`get_design_rules` が返す内容をそのまま守ってください。記憶で作らないこと。

- 図解の使用色は **3色以内**
- 全画面表示に使う画像は **1,920×1,080 px以上**
- テロップだけを並べない（画像・イラストを使う）
- 演者の顔へ被せない / セーフマージンを超えない
- 完了条件: **音量を0にして図解だけを見ても内容が理解できること**

### 画像認識で検査できること・できないこと

画像を読み取れるようになると、次が機械的に確認できます。

| 検査できる | 根拠 |
|---|---|
| 画像の解像度が 1,920×1,080 未満でないか | 数値基準 |
| 図解の使用色が3色を超えていないか | 数値基準 |
| テロップが演者の顔に重なっていないか | 工程7・工程8 |
| セーフマージンを超えていないか | 工程7 |

**検査できないもの**: 「この演出が場面に合っているか」という質の判断。
これは director の担当です。読み取り結果を根拠として `handoff("director", ...)` で渡してください。

## 顧客素材をAIへ入力してよいか — 未確認

**現行マニュアルに、AI生成・AI高画質化についてのルールがありません。**

- 生成物の内容が意図せず変化する可能性
- 顧客からお預かりした素材をAIサービスへ入力してよいか

この2点は共通マニュアルに記載がなく、`list_conflicts` でも「要確認」として扱っています。
**素材を投入する前にディレクターへ確認してください。** 勝手に「問題ない」と判断しないこと。

社内で生成した図解（顧客素材を含まないもの）は、この確認の対象外です。

## 役割の読み込み方

Codex にはサブエージェント機能がないため、MCPツールで役割を読み込みます。

```
1. list_agents             どの役割があるか見る
2. get_agent_role("design") 定義を読み込み、その役割として振る舞う
3. get_design_rules()       生成前の制約を引く
   （生成する）
4. handoff("director", ...) 担当外の判断を渡す
```

**担当外の判断を自分で決めないでください。** `handoff` は根拠が空だと警告を出します。

## 動作確認

```bash
codex
> get_agent_role("design") を読み込んで、その役割として振る舞ってください。
> そのうえで get_design_rules() を引いて、守るべき制約を列挙してください。
```

制約が3色以内・1,920×1,080以上を含んでいれば、Codexチームの準備は完了です。
