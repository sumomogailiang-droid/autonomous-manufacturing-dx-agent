## 1. 制作工程（全13工程）

### 工程1: 依頼・即レス　[正式記載]

**結論**: 依頼が来たら、すぐに一次返信する。

**何をするか**
- 連絡が来たら、まずすぐに一次返信をします。
- すぐ回答できないときは、具体的な時刻を伝えます。例:「現在○○の状況のため、○時までに回答いたします」
- 【着手報告】テンプレートで、着手と初校共有予定時刻を伝えます。
- 案件独自マニュアルやチャンネル独自ルールがある場合は、そちらを優先します。

**なぜ必要か**
- 返信がないと、依頼者は「見ていないのか、断られたのか」が判断できず、案件全体が止まります。
- 具体的な時刻を伝えると、相手は他の予定を組めます。

**よくある失敗**
- 「今日中に返します」のような曖昧な表現を使う（禁止されています）。
- 内容を確認してから返信しようとして、一次返信が遅れる。
- 不明点を自分の判断だけで処理してしまう。

**完了条件**
- 一次返信を送信済み。
- 回答時刻または初校共有予定時刻を、数字で伝えてある。

**関連マニュアル**: 2. はじめに / 5. 制作に関するやり取りの注意 / 7. チャットテンプレ

### 工程2: 権限・素材・納期確認　[正式記載]

**結論**: 素材の不備は、いちばん最初に見つける。

**何をするか**
- 別録りマイク素材の有無、カメラ内蔵マイクの音声、演者へのマイク装着を確認します。
- マイクがあるのに音声がない場合は連絡します。
- 素材のつながりから抜けている素材がないか確認します。挨拶や締めがない場合は素材漏れを疑います。
- 概要欄用素材や画面表示素材が共有されているか確認します。未共有素材は遅くともカット完了時に報告します。
- 画質、白飛び、通常画角、MTSファイルの注意事項を確認します。
- 権限が必要な場合、無断で「アクセス権限をリクエスト」を押しません。フロントディレクターへ連絡し、自分のメールアドレスも伝え、先方へ確認・招待してもらいます。
- アップロードや書き出し時間も納期に含めて計算します。

**なぜ必要か**
- 素材不備が納期直前に発覚すると、対応できない可能性があります。
- 無言の権限申請は、クライアントに不信感や混乱を与える可能性があります。
- 「編集は終わったが、アップロードで納期を超える」状態を防ぐためです。

**よくある失敗**
- 確認せず編集を始めて、途中で素材不足に気づく。
- スプレッドシートで無断で権限リクエストを押す。
- 書き出し時間を計算に入れず、納期を超える。

**完了条件**
- 素材確認の全項目をチェック済み。
- 不備があれば【素材不備の可能性の連絡】を送信済み。
- 不備がなければ「素材確認済みです」を送信済み。

**関連マニュアル**: 9. 素材確認 / 5. 制作に関するやり取りの注意 / 7. チャットテンプレ

### 工程3: シーケンス・画角・音声設定　[正式記載]

**結論**: 最初の設定を間違えると、大きな手戻りになる。

**何をするか**
- シーケンス設定を最初に正しく行います。
- 人物が小さすぎる場合は、最初に通常画角を調整します。
- 画角の数値は「モーション」でも変更できますが、「ソース」側で調整すると全体へ反映でき、事故を減らせます。
- 演者音声トラックへ上から順に、Multiband Compressor（プリセット「テレビ放送」）、ハードリミッター（最大振幅 -6.0dB）、クロマノイズ除去（10%）、ステレオエクスパンダー（ステレオ拡張 0%）を設定します。
- SEトラックはハードリミッター最大振幅 -20.0dB、BGMトラックは -29.0dB にします。
- グリーンバック素材は Lumetriカラー → Ultraキー → カラーマット → チョーク → マスク → スピル の順で処理します。
- 色調補正は必要な場合だけ行います。基本的には不要です。

**なぜ必要か**
- シーケンス設定を最初に間違えると、大きな手戻りになります。
- 撮影時は後から調整できるよう引きで撮影されている場合があるためです。
- 色調補正は動画ごとの色がバラバラになるのを防ぐため、実施前にディレクターへ連絡が必要です。

**よくある失敗**
- 最適な画角をディレクターへ確認せずに決めてしまう（チャンネルごとに違います）。
- 色調補正を無断で行い、動画ごとに色がバラバラになる。
- 音声エフェクトの順番や数値を自己流にする。

**完了条件**
- シーケンス・通常画角が確定している。
- 演者・SE・BGMの各トラックへ規定の数値を設定済み。
- 色調補正を行う場合はディレクターへ連絡済み。

**関連マニュアル**: 10. グリーンバック / 11. 音調整 / 18. 画角見切れ対策

### 工程4: 粗カット　[正式記載]

**結論**: 大きな不要部分だけを取り除く。自動ツールも必ず目視確認。

**何をするか**
- カット前に素材をネストします。
- 大まかな不要部分をカットします。
- 自動カット系ツールを使用した場合も、必ず自分の目と耳で確認します。

**なぜ必要か**
- ネストしておくと、素材差し替えへの対応がしやすくなります。
- 自動ツールは発声部分を誤って切ることがあるためです。

**よくある失敗**
- ネストせずにカットを始めてしまう。
- 自動カットの結果をそのまま信用する。
- 発声部分をカットしてしまう（絶対禁止）。
- 内容を独断でカットする（絶対禁止）。

**完了条件**
- 素材をネスト済み。
- 大きな不要部分を除去済み。
- 自動ツール使用箇所を目視・試聴で確認済み。

**関連マニュアル**: 12. カット / 4. 動画制作手順

### 工程5: 細カット　[正式記載]

**結論**: イヤホンで音を聞きながら、子音のタイミングに合わせて整える。

**何をするか**
- 重複箇所、言い直し、ケバ、テンポ、不自然な間を調整します。
- 必ずイヤホンを使い、音を聞きながら微調整します。
- 子音の発声タイミングに合わせます。
- ケバを取って不自然になるなら残してよいです。
- ボケやシュールな間は、意図があれば残してよいです。
- 「っ」がある言葉を詰めすぎないようにします。
- 笑い声・相槌は途中で切らず、完全に消すか最後まで残します。

**なぜ必要か**
- 機械的に詰めると、会話が不自然になり視聴者が離脱します。
- 相槌が発言と被る場合、途中で切ると聞き苦しくなるためです。
- 動画の雰囲気によっては、意図的な間が演出になります。

**よくある失敗**
- スピーカーで作業し、細かい音の粗に気づかない。
- 「っ」の前後を詰めすぎて不自然になる。
- 笑い声や相槌を途中でぶつ切りにする。
- 不要な無音や間延びを残したまま次工程へ進む。

**完了条件**
- 重複・言い直し・ケバの処理が完了。
- 子音の発声タイミングと合っている。
- 自然に聞こえる状態になっている。

**関連マニュアル**: 12. カット / 11. 音調整

### 工程6: カット確認　[正式記載]

**結論**: カット完了時点で提出し、カット感覚のフィードバックをもらう。

**何をするか**
- カット完了時点でディレクターへ提出します。
- カット感覚のフィードバックをもらいます。
- フィードバック待ちの間も、できる作業は進めます。

**なぜ必要か**
- カットの基準がずれたままテロップまで進むと、手戻りが非常に大きくなるためです。
- 待ち時間をゼロにすることで、納期に余裕が生まれます。

**よくある失敗**
- カット提出を飛ばして、テロップまで一気に進めてしまう。
- フィードバック待ちの間、完全に手を止める。

**完了条件**
- カット版をディレクターへ提出済み。
- フィードバックを受領し、反映済み。

**関連マニュアル**: 4. 動画制作手順 / 5. 制作に関するやり取りの注意

### 工程7: テロップ・表記統一　[正式記載]

**結論**: 1行15〜18文字。句読点は使わず半角スペース。表記揺れはゼロにする。

**何をするか**
- 演出なしの通常テロップを作ります。
- 複数人いる場合は、人物ごとのテロップ色を統一します。
- 1行15〜18文字を目安に、基本は1行。2行にする場合は上を短く、下を長くします。
- セーフマージン外へ出さず、テロップの底辺位置をずらしません。
- 原則として「、」「。」は使わず、半角スペースで対応します。
- 熟語以外の数字は原則半角英数字。金額はコンマを入れ、時刻は24時間表記にします。
- 「！」「？」は全角。断言している発言へ「？」を付けません。
- 意味のまとまりで改行します。主語がない場合は丸括弧で補います。
- 固有名詞は公式サイトなどで裏取りします。Wikipediaだけを根拠にしません。
- 編集後にフォント崩れがないか「グラフィックとタイトル」→「フォントを置換」で確認します。

**なぜ必要か**
- 文字数が多すぎると読み切れず、視聴者が内容を理解できません。
- 表記が揺れると、動画全体の信頼感が下がります。
- 固有名詞のミスは、クライアントの信用に直接関わります。

**よくある失敗**
- 聞こえたまま固有名詞を書いて、裏取りせずに提出する。
- 句読点を入れてしまう。
- 2行にしたとき上を長く、下を短くしてしまう。
- 報告なしでフォントを変更する。
- 演者ごとのテロップ色切り替えを間違える。

**完了条件**
- 全テロップが1行15〜18文字の目安に収まっている。
- 表記揺れが1つもない。
- 固有名詞をすべて裏取り済み。
- フォント崩れがない。

**関連マニュアル**: 13. テロップ / 15. 表記揺れ／開く漢字一覧 / 8. 分割編集時のフロー

### 工程8: 見出し・画像・図解・演出　[矛盾・要決定]

**結論**: 演出は6秒に1回が基本基準。ただし提出前チェックは10秒に1回で、矛盾している。

**何をするか**
- 強調テロップ、画角変化、演出を反映します。装飾テロップは基本スケール150以上にします。
- 内容理解に必要な画像を入れ、拡大縮小や上下左右の動きを付けます。
- 全画面表示では 1,920×1,080 未満の画像を使用しません。
- 画角アップは原則30%ずつ増やします（通常100%なら130%など）。
- 図解は音量を0にして図解だけを見ても内容を理解できる状態にします。使用色は3色以内。
- サブ見出しは、動画構成が理解できるように挿入します。
- デザインテロップを入れた場合は、テロップ・画角変化・SEをセットにします。

**なぜ必要か**
- 定点撮影が続くと視聴者が飽きるため、演出で変化を作ります。
- 見出しが弱いと、視聴者が動画内容を理解できず離脱します。
- 図解は、音声や文字だけでは頭に入りにくい内容を理解させるためのものです。

**よくある失敗**
- 同じデザインテロップやSEを連続して使う。
- 画角変化が120%など小さすぎて、違和感だけが残る。
- 装飾テロップが演者の顔へ被る、セーフマージンを超える。
- AIが出した見出しをそのまま信用し、動画を見て調整しない。
- 前半と後半で演出量にムラが出る。

**完了条件**
- 演出頻度の基準を満たしている（※6秒／10秒の矛盾はディレクター確認）。
- 装飾テロップがセーフマージン内かつ顔に被っていない。
- サブ見出しだけで動画構成が分かる。

> ⚠ 矛盾・要決定: 演出頻度は「6秒に1回」（演出・よくあるミス）と「10秒に1回」（提出前チェック）が衝突しています。勝手に統一せず、ディレクターへ確認してください。

**関連マニュアル**: 16. 演出 / 17. エンタメ演出 / 19. 図解演出 / 21. 画像演出 / 22. 見出し・サブ見出し作成

### 工程9: SE・BGM・音声処理　[正式記載]

**結論**: SEは画角変化・デザインフォント・画像挿入に。BGMは最後に入れる。

**何をするか**
- SEは、画角変化・通常フォントと異なるデザインフォント・画像挿入の場所に入れます。
- 通常フォントだけの場合は、原則SEを入れません。
- SEへ指数フェードを入れません。同じSEを2回連続で使いません。
- BGMは最後に挿入します。BGMへ途中カットを入れず、リミックスツールで長さを調整します。
- クリックノイズ対策は最後の書き出し前に行います（コンスタントパワーから指数フェードへ切り替え）。
- 途中広告やエンディングなどのmp4素材は、何も音量調整していないトラックへ置きます。
- 音源は DOVA-SYNDROME、効果音ラボ など利用可能な素材を使用します。

**なぜ必要か**
- SEが多すぎたり同じものが続くと、視聴者が飽きたり耳障りになります。
- リミックスはPremiere Proが重くなりやすいため、最後に行います。
- 書き出し後にBGMの音が消える場合があるため、確認が必要です。

**よくある失敗**
- SEそのものへ指数フェードを入れてしまう（クリックノイズ対策の指数フェードと混同）。
- 同じSEを2回連続で使う。
- エンディングへBGMが重なったまま提出する。
- イヤホンで音量確認をしない。

**完了条件**
- SEが規定の場所へ入っている。
- BGM挿入とリミックスが完了している。
- クリックノイズ対策が完了している。
- イヤホンで音量を確認済み。

**関連マニュアル**: 20. SE・BGM・クリックノイズ / 11. 音調整

### 工程10: 提出前チェック　[正式記載]

**結論**: 18項目のチェックリストと、誤字脱字チェックツールを必ず使う。

**何をするか**
- 提出前チェックリストの18項目をすべて確認します。
- 誤字脱字チェックツールを必ず使用し、検出された誤字・表記揺れをすべて修正します。
- ツールだけでなく目視確認も行います。
- FrameDetectorでFrame 1とFrame 2の両方をチェックし、マーカーが付いた箇所をすべて修正します。
- 画角見切れは、フル画質横のスパナ →「透明グリッド」で、見切れ部分がシマシマになっていないか確認します（必ず行うルール）。
- ディレクター提出時は「チェックリストに記載されている項目は見つかりませんでした」と記載します。
- 共有するチェックシートは、一般的なアクセスを「リンクを知っている全員」「編集者」へ変更します。

**なぜ必要か**
- 修正漏れは1箇所でもレベルマイナス（-5点）の対象になります。
- フレームずれはツールを使わないと目視では発見しきれません。

**よくある失敗**
- 誤字脱字チェックツールで検出できるミスを残したまま提出する（レベル0の条件）。
- FrameDetectorのFrame 1だけ確認してFrame 2を忘れる。
- 透明グリッドでの見切れ確認を省略する。

**完了条件**
- チェックリスト18項目がすべてチェック済み。
- 誤字脱字チェックツールでエラーがゼロ。
- FrameDetectorでフレームずれがゼロ。

> ＋ 改善候補（正式ルールではない）: モザイク・個人情報の確認、画像／BGM／SEのライセンス証跡の保管は、現行の正式チェック項目にありません。改善候補として別に管理してください。

**関連マニュアル**: 23. チェック / 18. 画角見切れ対策 / 15. 表記揺れ／開く漢字一覧

### 工程11: 書き出し・提出　[矛盾・要決定]

**結論**: 2026年4月23日更新でFrame.ioへ統一。ただし旧手順が残っており矛盾している。

**何をするか**
- Frame.ioへアップロードします。
- 同時にギガファイル便へプロマネとmp4をアップロードします（保存100日）。
- 管理シートへ格納し、チェックリストを添付し、工程別編集時間を共有します。
- プロマネ作成時は、メディアキャッシュを削除し、元素材を提出物から削除します。
- 「未使用のクリップを除外」にはチェックしません。
- フォルダごとアップロードし、案件の命名規則に沿って名前を付けます。
- 「まとめる」を実行する前にファイル名を確認します。

**なぜ必要か**
- 限定公開だと、クライアント公開時にコピーコンテンツ扱いとなり、再生数低下や警告が発生する可能性があるためです。
- 元素材を外すのは、提出物の容量を抑えるためです（元素材は別途保存します）。

**よくある失敗**
- 「未使用のクリップを除外」にチェックを入れてしまう。
- 元素材を提出用プロマネから外さずにアップロードする。
- ファイル名を確認せずに「まとめる」を実行する。
- アップロード時間を納期に含めていない。

**完了条件**
- Frame.ioへアップロード済み。
- ギガファイル便へプロマネとmp4をアップロード済み。
- 管理シートへ格納し、チェックリストを添付済み。

> ⚠ 矛盾・要決定: 提出方法が衝突しています。提出シート冒頭は「Frame.ioへ統一」、チェックは「YouTube限定公開を提出」、提出シート後半には限定公開手順が残存、修正では限定公開の概要欄を使用となっています。正式ルールとして統合しないでください。

**関連マニュアル**: 24. 提出 / 23. チェック / 7. チャットテンプレ

### 工程12: 修正・全体再チェック　[正式記載]

**結論**: 修正は本来0を目指す。指示箇所以外も動画全体を再チェックする。

**何をするか**
- 修正指示を受けたら必ず返信します。無言で着手して事後報告しません。
- 【着手報告】で、提出予定時刻を伝えます。
- 修正箇所をタイムコードで記録します。
- 動画尺が変わった場合は最新尺に合わせます。
- 修正後は指示箇所以外も動画全体を再チェックします。
- 進捗シートの動画、mp4、プロマネを最新版へ更新します。
- カット修正は時間がずれるため最後に行います。
- 初稿納期後24時間は、修正へ対応できるよう予定を空けておきます。

**なぜ必要か**
- 修正漏れは1箇所でもレベルマイナス（-5点）の対象です。
- カット修正を先に行うと、後続のテロップやSEの位置がすべてずれるためです。

**よくある失敗**
- 指示された箇所だけ直して、全体を見直さない。
- カット修正を最初に行い、他の要素がずれる。
- 無言で修正に着手する。
- 進捗シートの各ファイルを最新版へ更新し忘れる。

**完了条件**
- 修正指示へ返信済み。
- 全修正箇所を対応済み、かつ動画全体を再チェック済み。
- 進捗シートの動画・mp4・プロマネが最新版。

> ⚠ 矛盾・要決定: 修正の現行文面には限定公開の概要欄を使う説明が残っており、Frame.io方針と矛盾しています。Add MarkerのURLは省略されているため、完全なURLを推測しないでください。

**関連マニュアル**: 25. 修正 / 23. チェック

### 工程13: 保存・切り抜き・育成　[正式記載]

**結論**: プロマネと素材は1年間保存。切り抜きはクライアントOK後に制作。

**何をするか**

**よくある失敗**

- 修正前素材を使用して切り抜きを作る。
- 1年経過前に独断でデータを削除する。

**完了条件**

dB（デシベル）は音の大きさの単位。数字が小さい（マイナスが大きい）ほど音が小さい。

| 項目 | 基準値 | 種別 | 補足 |

## 3. 品質評価基準

### レベルマイナス（-5点・重大ミス）

- 誤字脱字・固有名詞ミスが累計7箇所以上
- テロップ、見出し、SEなどのフレームずれが5箇所以上
- テロップ位置や、途中で止まるエフェクトミスが3箇所以上
- 子音の発生とテロップ表示のタイミングずれが3箇所以上
- 修正漏れが1箇所以上
- 納期に間に合わない
- 他の人に巻き取られる
- マニュアルを守れば防げる、姿勢・基準値の問題によるミス

### レベル0（0点・研修段階）

- 誤字脱字・固有名詞ミスが3個以上
- 誤字チェックツールで検出できるミスが1つ以上残る
- フレームずれが2箇所以上
- テロップ位置・エフェクトミスが2箇所以上
- 子音とテロップ表示のずれが2箇所以上
- 不要な無音や間延びが5箇所以上
- クリックノイズ、音量差、マイク切り替えなどの音声トラブルが2箇所以上
- 強調時の見出し削除漏れなど、見出しミスが1箇所以上
- 演者ごとのテロップ色切り替えミスが1箇所以上

### レベル1（+3点・現場標準）

- 誤字脱字・固有名詞ミス・表記揺れが3箇所未満
- フレームずれが0
- テロップ位置・エフェクトミスが0
- 子音と表示タイミングのずれが0
- 不要な間の指摘が5箇所未満
- 見出しテロップミスが0
- 演者ごとのテロップ色切り替えミスが0
- マニュアルを守れている状態

### レベル2（+5点・プロレベル）

- レベル1のミス項目がすべて0
- ディレクターの確認なしでもクライアントへ提出できる品質

## 4. 事故防止マップ（原因 → 事故 → 防止策 → 最終確認）

### マルチカメラで音声までカメラ切り替えされる　[正式記載]

- **原因**: 音声トラックをネストしてしまった。
- **起きる事故**: カメラを切り替えたときに、音声まで別カメラの音へ切り替わる。
- **防止策**: 音声トラックはネストしない。映像だけV1・V2・V3をそれぞれネストし、さらにネストする。
- **最終確認**: カメラ切り替え箇所で音声が途切れたり音質が変わっていないか、イヤホンで通し確認する。

### サブシーケンス挿入で必要なクリップが消える　[正式記載]

- **原因**: トラックターゲットを間違えたまま「上書き」を実行した。
- **起きる事故**: 既存の必要なクリップが上書きされて消える。
- **防止策**: 挿入前にタイムラインのトラックターゲットを必ず確認する。「ネストとして、または個別クリップとしてシーケンスを挿入または上書き」はOFFにする。
- **最終確認**: 挿入直後に、対象範囲のクリップが欠けていないかタイムラインで目視確認する。

### 素材不備が納期直前に発覚する　[正式記載]

- **原因**: 素材確認を最初に行わなかった。挨拶や締めの欠落に気づかなかった。
- **起きる事故**: 納期直前に素材不足が判明し、対応できない。
- **防止策**: 工程0で素材確認を完了させる。未共有素材は遅くともカット完了時に報告する。
- **最終確認**: 【素材不備の可能性の連絡】または「素材確認済みです」のどちらかを送信済みか確認する。

### 無言の権限申請でクライアントが混乱する　[正式記載]

- **原因**: クライアント管理のスプレッドシートで「アクセス権限をリクエスト」を無断で押した。
- **起きる事故**: クライアントに不信感や混乱を与える。
- **防止策**: フロントディレクターへ連絡し、自分のメールアドレスも伝え、ディレクターから先方へ確認・招待してもらう。
- **最終確認**: 権限が必要になったとき、リクエストボタンを押す前にディレクターへ連絡したか確認する。

### フレームずれが残ったまま提出する　[正式記載]

- **原因**: FrameDetectorのFrame 1だけチェックし、Frame 2を確認しなかった。
- **起きる事故**: フレームずれが5箇所以上でレベルマイナス（-5点）。
- **防止策**: FrameDetectorでFrame 1とFrame 2の両方をcheckし、付いたマーカー箇所をすべて修正する。
- **最終確認**: 提出前チェックリストの「FrameDetectorでフレームずれを0にした」にチェックが入っているか確認する。

### 画面が見切れたまま提出する　[正式記載]

- **原因**: 透明グリッドでの見切れ確認を省略した。
- **起きる事故**: 素材の上下左右が切れた状態で納品される。
- **防止策**: フル画質横のスパナ →「透明グリッド」で、見切れ部分がシマシマになっていないか確認する（必ず行うルール）。
- **最終確認**: 提出前チェックリストの「画面見切れがない」を確認する。

### 固有名詞を間違えたまま提出する　[正式記載]

- **原因**: 聞こえたまま見切り発車で書いた。Wikipediaだけを根拠にした。
- **起きる事故**: 固有名詞ミスが累計7箇所以上でレベルマイナス（-5点）。クライアントの信用低下。
- **防止策**: 人物名・企業名・団体名・専門用語・熟語・慣用句は公式サイトなどで裏取りする。分からない場合はディレクターへ報告する。
- **最終確認**: 提出前チェックリストの「固有名詞をすべて裏取りした」を確認する。

### BGMが書き出し後に消えている　[正式記載]

- **原因**: リミックス処理後の書き出し結果を確認しなかった。
- **起きる事故**: 納品動画にBGMが入っていない。
- **防止策**: リミックスはPremiere Proが重くなりやすいため最後に行い、書き出し後に音が消えていないか確認する。
- **最終確認**: 書き出したmp4をイヤホンで再生し、BGMとエンディングの重なりを確認する。

### 納期にアップロード時間が入っていない　[正式記載]

- **原因**: 編集完了時刻だけを納期の基準にした。
- **起きる事故**: 「編集は終わったが、アップロードで納期を超える」状態になる。納期遅延はレベルマイナス（-5点）。
- **防止策**: アップロードや書き出し時間も納期へ含めて逆算する。複数工程を同時に行わず1工程ずつ進める。
- **最終確認**: 納期の何時間前に書き出しを開始するか、着手時点で決めておく。

### 納期遅延を事後報告してしまう　[正式記載]

- **原因**: 間に合わせようとして、連絡を先延ばしにした。
- **起きる事故**: 事後報告は禁止されている。依頼者側が代替手段を取れない。
- **防止策**: 間に合わない可能性が出た時点で依頼者へ連絡する。調整後の納期が分かる場合は同時に伝える。
- **最終確認**: 納期に間に合わないと分かった瞬間に連絡したか確認する。

### カット修正で全体がずれる　[正式記載]

- **原因**: カット修正を最初に行った。
- **起きる事故**: テロップ・SE・画像などの位置がすべてずれる。
- **防止策**: カット修正は時間がずれるため最後に行う。
- **最終確認**: 修正後に指示箇所以外も含めて動画全体を再チェックする。

### 切り抜きを作り直しになる　[正式記載]

- **原因**: クライアントOV前に切り抜きを制作した。修正前素材を使用した。
- **起きる事故**: 本編修正が入り、切り抜きがすべて作り直しになる。
- **防止策**: クライアント承認後の完成mp4で切り抜きを制作する。
- **最終確認**: 納品前チェックの「クライアント承認後素材を使用」を確認する。

## 10. 切り抜き動画

### 業務フロー

1. 本編編集中に切り抜き候補を探す
2. 本編初稿提出時に候補タイムスタンプも提出
3. 本編修正
4. クライアント承認を待つ
5. 承認後の完成mp4で切り抜きを制作
6. ディレクターへ提出
7. 修正対応
8. 最終OK後に納品・投稿

### 禁止

- クライアントOK前に制作しないでください。
- 修正前素材を使用しないでください。

### 書き出し

- 縦型: 9:16 / 1,080×1,920 / YouTube Shorts・TikTok・Instagramリール
- 横型: 16:9 / 1,920×1,080
- 形式: MP4 / H.264
- 命名: チャンネル名_切り抜き_通し番号（元動画とタイムコードを記録します。）

### タイトル4要素

1. SEOキーワード
2. 具体的内容
3. 視聴者のメリット
4. 差別化要素

重要キーワードは前半へ置きます。全角28〜40文字程度が目安です。
